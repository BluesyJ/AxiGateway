# ItbigtecGateway 产品目标与建设方案 V3.3

日期：2026-11-20。项目原工程名和仓库名为 AxiGateway，现有目录、包名及运行配置保持不变。

负责人已认可 V3.3 的产品方向，并授权通过仓库同步目标。本文保留完整研发内容和六个交付版本，数量、时限与运行指标均为项目验收目标。各项工程设计、阶段归属及实施授权按 [目标对齐提案](proposals/20261120-enterprise-governance-v33.md) 和 [ROADMAP](ROADMAP.md) 管理。

## 一、立项依据

### （一）项目背景

企业在多个应用中接入模型和工具时，普遍面临接入配置分散、应用凭据混用、工具发布缺少统一入口、人员变动后权限未及时回收等管理问题。随着 MCP 工具、Skill 和 Agent 的使用增加，管理对象从模型接口扩展到资源的发布、授权、执行和停用。

项目围绕这些管理需求建设统一的软件入口，将模型访问、工具广场、审批上下架、人员撤权和调用查询集中到同一系统，减少业务应用重复建设接入与管理功能的工作。

### （二）项目建设目的

**提供可直接演示的企业 AI 治理系统。** 系统展示员工发现和使用工具、管理员审核发布资源、工具下架和员工离职后访问被阻断的完整过程。该成果用于客户方案演示、需求沟通和技术验证，使统一治理方案具备可操作的实物载体。

**形成可安装、可试用的网关应用。** 系统提供标准安装包、管理界面和操作手册，支持在独立测试环境部署，完成模型接入、权限分配、限额控制和调用查询。试用版本用于收集实际操作与运行反馈，推进产品功能完善。

**形成可复用的软件产品资产。** 项目交付模型管理、工具目录、审核发布、身份联动和审计查询模块，并配套接口说明、测试集与部署资料，为后续同类场景提供统一的软件基础。

### （三）总体目标与应用场景

项目建设覆盖模型、MCP 工具、Skill 和 Agent 的统一接入与治理系统。员工通过资源门户查找并使用获准资源；管理员通过管理控制台配置访问权限、审核资源、执行上下架和处理人员停用；运维人员查询调用结果、用量及管理操作记录。

项目按六个系统版本递进交付：模型监测最小系统、模型访问管理系统、工具广场演示系统、企业身份与撤权演示系统、多类型资源治理系统、可安装试用版。第四阶段交付模型与 MCP 工具的企业治理演示，第五阶段交付包含 Skill、Agent 和受控执行的完整方案演示，第六阶段交付面向试用的发布包。

### （四）实施组织

项目按照版本目标组织需求、开发、测试和验收。每个版本交付可运行软件及对应测试结果，阶段验收以功能完成情况和指标达成情况为依据。项目进展纳入双周汇报，报告已交付版本、未完成事项和下一阶段安排。

## 二、项目研发内容和目标

### （一）总体方案

ItbigtecGateway 建设资源门户、治理服务、调用网关和受控执行环境，统一管理模型、MCP 工具、Skill 和 Agent。员工在门户发现资源、发起任务和领取结果；管理员在控制台完成资源审核、权限配置、版本发布、预算管理和审计查询；业务应用通过网关使用获准的模型与工具。

系统内部由治理服务集中保存资源、版本、发布状态和授权规则，门户、调用网关及执行环境使用同一授权结果。企业身份系统提供人员与组织信息，代码及制品仓库保存研发成果，检查与部署系统承担构建和服务部署，业务系统继续管理数据权限。项目通过标准接口连接这些系统，形成从资源提交到运行使用的完整方案。

| 系统组成 | 建设内容与职责 |
|---|---|
| 员工门户与管理控制台 | 资源广场、提交审核、任务交互、结果领取、授权管理、预算和审计查询 |
| 资源治理服务 | 资源登记与版本、审核记录、发布状态、统一授权、Skill 交付规则、人员停用联动 |
| 模型、MCP 与 Agent 网关 | 认证接入、调用授权、限流与额度执行、协议适配、请求路由及调用记录 |
| Skill 交付与受控执行 | 获准文件分发、服务端运行、会话与任务管理、执行隔离、业务产物交付 |
| 用量与审计服务 | 个人和生产用量归集、部门预算、调用追踪、治理操作记录及采集健康 |
| 企业系统连接 | 身份源、代码与制品库、检查部署流程、业务 API 和受控数据查询服务 |

### （二）主要研发内容

**1. 资源广场与统一资源管理**

建设统一资源广场，按模型、工具、Skill 和 Agent 分类展示，提供检索、用途说明、版本信息、使用条件及操作入口。员工只看到获得发现权限的已发布资源，并根据执行、调用或下载权限使用相应能力。

资源登记统一保存资源标识、类型、负责人、所属部门、服务地址或制品引用、版本及交付方式。审核结果绑定具体版本，执行配置引用获准版本；同一资源的新版本独立审核，历史发布记录保留。单个 Skill 独立设置权限和状态，下架一个 Skill 不影响同仓库中的其他资源。

**2. 员工提交、审核与版本发布**

员工提交资源用途、负责人、接入方式及代码或制品引用。审核服务汇集代码、依赖、安全检查与功能测试结果，管理员在审核页面批准或驳回。管理员发布官方资源时直接进入资源配置和发布流程，保留检查及发布记录。

发布服务根据资源类型完成接入：已有 MCP 或 Agent 服务登记地址、认证方式和协议；需要托管的服务先通过部署系统启动，再登记调用入口；Skill 保存文件版本并绑定执行配置。登记服务地址与部署服务分别执行，避免资源已登记而实际无法运行。

系统在审核通过、部署或注册成功、授权配置生效后开放资源入口。发布失败时保留审核结果、失败步骤和受控错误信息，新版本不进入可用目录；原有已发布版本保持原状态。更新重新履行审核，版本回退指向此前获准版本并保留操作记录。下架同时关闭发现、调用、执行和下载入口。

**3. 企业身份、统一授权与离职撤权**

对接企业身份源，同步员工、部门和人员状态，为生产应用建立独立服务身份。授权以经过认证的员工或应用为主体，结合资源、版本和操作判断访问范围；发现、调用、执行、下载、发布和管理分别授权。门户不另存一套访问名单，各入口向统一授权服务查询或使用有明确失效期限的授权缓存。

Agent 代员工执行任务时，同时检查应用自身权限和员工权限；以两者共同允许的范围执行。独立生产任务按应用的生产授权运行，计费归属与员工访问权限分别判断。客户端自报标签仅用于展示，不能作为员工身份或部门归属依据。

员工停用后，系统撤销个人会话和凭据，使授权缓存失效，阻断其新调用、新任务、文件下载和结果领取。运行中的任务停止接受该员工的后续交互；支持取消的执行器终止任务，已经发往外部系统的操作保留执行状态。系统记录停用时间、撤权结果和后续拒绝，其他员工及独立生产服务按自身授权继续运行。

**4. 模型接入、MCP 工具与业务系统连接**

模型网关提供统一模型入口，管理应用凭据、模型范围、请求限流和用量额度，支持普通与流式调用。上游地址及凭据由管理侧维护，应用通过自身身份访问网关。模型转发、协议适配、认证及凭据管理复用成熟组件。

MCP 网关提供工具发现与调用，统一执行工具授权、参数校验、超时和限流。接入方式包括登记已有 MCP 服务、将经过筛选的 OpenAPI 操作封装为工具，以及通过受控查询服务连接数据库。查询服务限定表、字段与记录范围，不向模型开放任意数据库操作。

工具权限控制能否调用该工具，业务系统权限控制本次调用能访问哪些数据。支持个人授权的系统使用对应员工凭据；使用服务账号的系统通过标准身份组件生成和校验绑定员工、应用及任务的短期身份凭证，由工具服务据此执行数据权限。调用方填写的员工名或部门标签不进入授权判断。

**5. Skill 版本、交付方式与文件保护**

建立 Skill 注册与交付服务，支持单文件和文件包、版本登记、审核及停用。每个 Skill 分别配置执行权限、下载权限和交付方式，支持“允许授权下载”和“仅服务端执行”两类资源。交付服务检查资源状态、获准版本、用户权限和交付方式后提供文件；执行服务使用运行身份加载指定版本。

仅服务端执行的 Skill 文件保存在受控存储中，员工不能通过资源详情、原文接口、存储地址或执行环境文件接口直接读取。运行环境隔离 Skill 文件与业务产物，限制文件访问和网络出口，输出交付只开放获准的业务产物。验收使用哨兵文件检查直接读取、越权下载和诱导输出路径。

允许下载的 Skill 可在本地客户端使用，后续模型和企业工具调用继续经过网关。已经下载到终端的文件无法通过撤权收回；要求持续受控的能力以服务端执行方式交付。

**6. 受控执行环境、Agent 与任务管理**

提供服务端执行入口，管理员工会话、任务、执行状态、流式返回和业务结果。任务绑定员工、应用、获准资源版本及权限范围，执行环境限制可用模型、工具、文件目录和外部连接，并设置运行时限和资源上限。任务查询及结果领取均检查当前访问权限和任务归属。

企业已有 Agent 通过 Agent 网关登记服务地址和接入协议，继续在原环境运行。Agent 的内部模型请求和 MCP 请求分别接入对应网关，使任务入口与内部调用均受控制。本地客户端直接连接模型和 MCP 网关，获准下载的 Skill 在本地加载。

业务产物写入独立结果存储，门户凭文件标识提供领取入口，员工只能取得自己有权访问的任务结果。下载地址和结果接口执行相同权限校验，人员撤权后停止提供新结果访问。

**7. 开发与生产隔离、部门预算和审计监控**

个人开发、生产应用采用独立身份、权限和额度。生产用量归属应用及部门，不扣减调用员工的个人开发额度。部门设置共享预算，应用设置独立上限，系统同时执行适用的部门和应用约束。

额度支持请求数、Token 和费用估算。Token 与费用预算在请求前预留额度、请求结束后按可取得的用量结算，对未取得的用量保留未结算状态，避免按零消耗释放额度。费用预算只对已配置价格及版本的资源启用，缺少价格时执行请求数和 Token 限额。费用统一标为“估算（非账单）”，按币种、来源与价目版本分组；未知用量保留未知状态，不补零、不混合不同来源统计。

调用监测关联员工、应用、任务、请求和资源，展示状态、耗时、分来源 Token、费用估算及采集缺口。治理审计独立持久化审核、发布、授权、停用和预算变更；关键治理操作成功返回前保存状态及审计记录，存储失败返回失败。既有尽力采集的调用事件用于观测，不能作为完整治理审计的唯一依据。正文采集默认关闭，凭据不进入记录，业务任务内容与统计数据分别存储和授权。

**8. 安装交付与运行维护**

提供可独立部署的发布包、配置检查、演示数据、操作手册及接口说明。演示环境采用模拟上游、测试身份和合成业务数据。维护工具覆盖资源配置、权限、已持久化记录及必要制品的备份恢复，提供版本升级、回滚和运行健康检查。

### （三）关键接口与业务流程

系统围绕统一资源和授权模型设计接口，门户、管理控制台、网关与执行器共享资源标识、版本和任务标识。接口职责如下。

| 接口能力 | 输入与返回 | 执行规则 |
|---|---|---|
| 资源登记与版本管理 | 提交资源类型、负责人、服务或制品引用；返回资源及版本标识 | 新版本独立保存，审核绑定具体版本 |
| 审核与发布 | 提交审核结论和目标版本；返回发布状态及步骤结果 | 接入与授权成功后开放入口，失败保留记录 |
| 统一授权判定 | 接收可信主体、应用、资源、操作和任务上下文；返回允许或拒绝及策略版本 | 同时检查身份、资源状态、操作权限和适用额度 |
| 调用与任务执行 | 提交模型请求、工具参数或任务；返回请求标识、任务状态和结果 | 网关及执行器执行授权，内部调用保留关联关系 |
| Skill 与结果交付 | 提交资源版本或任务文件标识；返回获准文件 | 分别校验交付方式、下载权限和任务归属 |
| 停用与治理查询 | 接收资源下架或人员停用事件；返回处理状态，提供审计查询 | 撤销相关访问并记录生效结果 |

资源发布流程为“提交资源—检查与审核—部署或登记—配置授权—开放入口”；使用流程为“身份认证—资源与操作授权—调用或执行—返回结果—归集用量”。Skill 下载单独检查交付方式，业务结果领取单独检查任务归属。下架或人员停用触发授权更新，使目录、直接接口和旧会话遵守一致的访问状态。

### （四）技术路线与 AI Native 产品策略

项目在现有开源模型网关基础上扩展资源治理能力，复用成熟的协议适配、认证、凭据管理、身份集成及执行隔离组件，重点研发资源门户、审核发布、统一授权集成、Skill 交付控制和企业系统连接。模型转发层保持可替换，不 fork 底层网关，不自行实现认证协议或虚拟 Key。

模型和 Agent 承担任务理解与执行编排，资源权限、发布状态、额度和文件交付由确定性规则控制。项目依次交付模型基础、工具治理、企业身份与预算、多资源完整方案及试用版本；每个版本保留已有能力，并以可运行系统验证新增能力。

## 三、现有开发条件和工作基础

现有原型已实现模型请求转发、元数据采集、事件存储和查询仪表盘。查询界面包含总览、趋势、请求列表、模型汇总、客户端汇总和采集健康六类视图，支持独立演示数据。

现有验证覆盖普通与流式请求、访问拒绝、异常返回、事件存储和前端查询。2026年11月19日查阅的仓库版本具有已通过的云端自动化检查记录。模型监测原型构成第一阶段的开发基础；应用级权限与限额、工具发布、企业身份联动和撤权属于后续版本的新增功能。

工具发布、授权访问及人员撤权作为统一治理方案的主要演示场景。

本章指标为项目建设与验收目标。功能实验使用模拟上游、测试身份和合成数据；现有完成情况见第三章。

| 阶段 | 交付的系统版本 | 版本达到的状态 |
|---|---|---|

### 第一阶段：交付模型监测最小系统

**交付成果：** 一套包含统一模型入口、事件存储和查询仪表盘的最小系统，附安装说明、演示数据和启动入口。系统支持从调用发起到历史查询的完整操作。

**建设内容：** 集成现有模型接入和监测模块，整理安装配置，完成普通请求、流式请求、错误处理和历史查询功能。

**验收指标：**

- 配置 2 个模型入口，接入 2 个测试应用，覆盖普通与流式调用。
- 在正常运行条件下完成 100 次模拟调用，持久化记录数量与调用数量一致，支持按时间、模型和应用标签查询。
- 页面刷新和正常重启后，已持久化的历史记录保持可查；存储故障场景显示采集异常或缺口。
- 在全新测试环境按安装说明完成部署，并运行配套演示。

### 第二阶段：交付模型访问管理系统

**交付成果：** 一套带应用管理、凭据管理、模型授权和限额配置功能的模型网关系统。管理员可以在控制台完成应用接入、授权、停用和用量查询。

**建设内容：** 增加独立应用凭据、模型访问范围和每分钟请求数限额，将调用记录关联到可信应用身份，按应用展示 Token 用量。

**验收指标：**

- 为 2 个测试应用分别配置独立凭据、模型访问范围和限额。
- 完成正常调用、错误凭据、模型越权、限额触发和凭据停用 5 类验收场景；拒绝结果与策略一致。
- 停用一个应用凭据后，后续请求被拒绝，另一个应用继续正常调用。
- 控制台分别显示两个应用的调用次数、结果和分来源用量。

### 第三阶段：交付工具广场演示系统

**交付成果：** 一套包含员工工具广场和管理员审核页面的 MCP 工具管理系统，内置知识检索、计算和模拟业务查询 3 个演示工具。

**建设内容：** 建立资源标识、版本和操作权限，完成员工提交与管理员官方发布两条路径；对接检查、部署和服务登记，提供工具检索、分类、详情及调用入口。3 个工具分别覆盖已有 MCP 服务、OpenAPI 转工具和合成数据受控查询。

**验收指标：**

- 3 个工具均完成提交、审核、上架、调用和下架的完整操作。
- 管理员能够批准或驳回提交；未经批准的工具不进入可用目录，也不能通过接口调用。
- 获授权用户能够使用工具，未授权用户通过页面或直接接口访问均被拒绝。
- 下架操作成功返回后 60 秒内，工具停止接受新调用，旧链接和直接接口同步失效。
- 完成 1 次管理员官方发布、1 次版本更新与重新审核、1 次发布失败及 1 次获准版本回退；失败版本不开放入口，原发布版本不受影响。
- 系统保留提交、审核、上下架和调用记录，支持按工具查询；关键治理记录保存失败时，相应操作不能返回成功。

### 第四阶段：交付企业身份与撤权演示系统

**交付成果：** 一套面向模型与 MCP 工具的企业治理演示系统，包含统一登录、部门授权、开发生产隔离、共享预算、员工停用和审计查询。演示数据包含 2 个部门、5 个测试用户和独立生产服务身份。

**建设内容：** 对接 1 个测试身份源，建立员工、部门与资源权限的关联，实现人员停用和权限回收；分离个人开发与生产服务的权限及用量记录，增加部门共享预算、应用上限和业务系统身份传递。

**验收指标：**

- 两个部门的用户只能发现和使用各自获准的模型与工具。
- 身份源停用员工成功返回后 60 秒内，该员工旧会话和个人凭据发起的新请求全部被拒绝。
- 员工停用不影响其他获授权员工；独立生产服务继续按照自身权限运行。
- 用同一员工分别发起个人开发调用和生产应用任务，消耗分别归入个人与生产额度；完成请求数、Token 和配置价格下费用估算 3 类额度触发，部门额度与应用上限均能拒绝超限新请求。
- 1 个模拟业务工具按可信员工身份返回不同数据范围，伪造员工标签不能越权；并发额度预留和缺失用量均不能按零消耗放行。
- 系统能够查询资源审批、权限变更、员工停用及后续访问拒绝记录。
- 完成“提交工具—审批发布—员工使用—工具下架—重新上架—员工离职撤权”的连续演示。

本阶段完成模型与 MCP 工具的核心治理演示，用于展示工具上下架、部门管理、开发生产隔离和离职撤权。

### 第五阶段：交付多类型资源治理系统

**交付成果：** 一套覆盖模型、MCP、Skill 和 Agent 的完整方案演示系统，包含 2 个不同交付方式的 Skill、1 个已有 Agent 接入样例，以及可操作的服务端任务、流式状态和结果领取页面。

**建设内容：** 建设 Skill 版本与交付服务、受控执行环境和 Agent 网关，复用统一资源、授权、预算及审计机制。将服务身份、员工身份和任务关系贯穿模型与工具调用，隔离 Skill 原文和业务产物。

**验收指标：**

- 在同一资源仓库登记 2 个 Skill，1 个允许授权下载，另 1 个仅服务端执行；单独下架其中一个，另一个按原授权继续使用。
- 服务端执行固定获准版本，员工可查看任务状态、流式结果及业务产物；他人任务和撤权后的结果领取请求均被拒绝。
- 对资源详情、原文接口、存储链接、执行环境文件接口和任务输出执行哨兵检查，普通员工无法通过这些测试路径取得仅服务端执行的 Skill 原文。
- 1 个已有 Agent 经网关完成获授权的模型及工具调用，内部请求关联到同一任务；超出员工或应用权限范围的请求被拒绝。
- 人员停用成功返回后 60 秒内，旧会话发起的新任务、受控下载和结果领取均被拒绝；已下载文件保留在终端。
- 完成从资源提交、版本发布、授权使用、业务结果领取，到资源下架和离职撤权的完整演示；查询界面关联员工、应用、任务、资源与调用结果。

### 第六阶段：交付可安装试用版

**交付成果：** 一套支持 Windows x64 环境独立部署和试用的软件发布包，包含安装配置、演示数据、操作手册、备份恢复工具及版本说明。试用系统配置不少于 10 个测试账号。

**建设内容：** 集成已完成模块，完善配置校验、异常提示、备份恢复和升级操作，开展稳定性测试及使用评价。

**验收指标：**

- 在全新测试环境完成安装、配置和主要业务流程，安装过程不依赖开发目录。
- 在发布包注明的测试环境中，模拟上游正常响应、请求符合授权及限额的条件下，以并发数 10 持续发起调用，连续运行 30 分钟，请求成功率达到 99% 以上。预设的权限拒绝、限额拒绝和故障注入分别统计；测试环境配置、请求样本和统计口径随测试报告交付。
- 完成 1 次备份恢复和 1 次版本回滚演练，恢复后的已持久化配置、权限、资源状态和记录与备份一致。
- 10 个测试账号覆盖资源发现、授权使用和调用查询；演示覆盖模型、MCP、Skill 下载、服务端执行及已有 Agent 接入，管理员完成审核、版本更新、下架及账号停用。
- 受控执行完成文件越权、网络出口及运行超时 3 类隔离检查；凭据哨兵不出现在调用记录和审计记录中。
- 交付测试报告、使用问题清单和下一版本改进清单，形成可持续迭代的试用版本。

### 阶段验收管理

各阶段按交付版本和验收指标组织测试，记录通过项、失败项及修正结果。前一版本的能力在后续版本中持续保留并执行回归检查。双周汇报以系统版本、功能完成情况和指标结果呈现项目进展。

## 五、项目风险评估与管理

| 风险 | 控制措施 |
|---|---|
| 功能范围扩大导致交付延期 | 按六个版本控制建设范围，新增需求进入后续版本清单 |
| 授权与资源状态不一致 | 对页面入口、直接接口、旧会话和旧链接执行一致的访问校验 |
| 人员停用后权限残留 | 对身份状态同步、凭据失效和权限缓存进行联合测试，以60秒撤权目标验收 |
| Skill 原文或业务数据泄露 | 隔离源文件与产物，限制运行环境及下载路径，使用哨兵验证文件访问与输出，业务服务执行数据权限 |
| 治理记录缺失或额度统计偏差 | 独立持久化治理操作，额度预留与结算分离，未知用量保留未结算状态 |
| 依赖兼容与升级故障 | 固定发布版本和依赖，执行回归检查，提供备份及回滚操作 |
| 部署和使用门槛过高 | 通过全新环境安装测试、标准演示数据和操作手册完成交付验证 |

**不做的事：** 本项目不开展模型训练、GPU 调度，不替代企业身份源、代码仓库和业务数据库权限体系，不承诺收回已下载文件或撤销已经完成的外部操作。正文采集默认关闭，演示数据与实际业务数据分离；真实模型调用及客户环境接入执行独立授权。
